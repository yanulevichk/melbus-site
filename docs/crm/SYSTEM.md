# MELBUS OS — внутренняя система (CRM «Пульт», приложение бригады, страница клиента)

Версия 0.1 · 23.11.2026 · источник правды для разработки. План для владельца (простыми словами) — Claude Docs, ссылка в CLAUDE.md.
Прототипы дизайна: `public/proto/app/` (приложение бригады, телефон) и `public/proto/crm/` (Пульт, компьютер) — на сайте
`/proto/app/` и `/proto/crm/` (noindex, Disallow /proto/).

## 1. Зачем

Обещание MELBUS — **фиксированная цена и порядок**. Система должна:
1. не терять заявки (сайт, телефон, WhatsApp, Instagram → одна лента);
2. превращать заявку в оферту и заказ без пересчёта руками (та же формула `calc()` из `src/data/move.ts`);
3. планировать бригады и бусы на неделю;
4. вести каждый переезд по шагам: время, фото, коробки по QR, подпись клиента — **доказательная база** на случай спора
   («повредили шкаф» → фото «до» показывают царапину до начала работ);
5. любые доп. работы — только с согласия клиента ДО начала (УТП), согласие хранится;
6. считать фактические часы → прибыль заказа и **уточнять нормы минут на вещь** (цена становится точнее);
7. клиент видит, что происходит: страница переезда, коробки с фото, QR на коробке.

## 2. Части системы

| Часть | Для кого | Где | Устройство |
|---|---|---|---|
| Сайт + форма (есть) | клиент | melbus.pl | любой |
| **Пульт (CRM)** | владелец, менеджер-диспетчер | `/team/` → позже crm.melbus.pl | компьютер, телефон |
| **Бригада (PWA)** | бригадир, грузчики, водители | `/app/` → позже app.melbus.pl | телефон, ставится на экран «как приложение», работает без интернета |
| **Страница переезда** | клиент | `/t/<токен>` (4 языка) | телефон |
| QR на коробке | клиент, бригада | `/b/<код>` | камера телефона |
| Telegram-бот (есть) | менеджеры | группа «Melbus заявки» | — |

## 3. Роли и доступ

- **Владелец** — всё, включая финансы и настройки цен.
- **Менеджер** — заявки, оферты, расписание, заказы, сотрудники (без зарплатной ведомости — по желанию владельца).
- **Бригадир** — в приложении: свои заказы, все шаги, подпись клиента, доп. работы, оплата у клиента (терминал).
- **Грузчик / упаковщик / водитель** — в приложении: свои заказы, сканирование коробок, фото, своё время.
- **Клиент** — без аккаунта: подписанные ссылки (оферта, страница переезда, согласие на доп. работы).

Вход: Пульт — Cloudflare Access (письмо с кодом на e-mail, бесплатно до 50 человек) + роль в БД.
Бригада — телефон + 4-значный PIN (устройство запоминается, сессия 30 дней, PIN сбрасывает менеджер).

## 4. Жизненный цикл

```
Заявка (lead)          new → contacted → video → offer_sent → won | lost(причина)
Оферта (offer)         draft → sent → viewed → accepted | declined | expired   (версии v1, v2…)
Заказ (job)            booked → confirmed(задаток) → today → in_progress → done → closed(оплачен, фактура) | cancelled
Шаги заказа (stage)    1 Выезд · 2 Прибытие · 3 Осмотр и защита · 4 Упаковка/разборка · 5 Погрузка · 6 В пути ·
                       7 Выгрузка · 8 Сборка и расстановка · 9 Приёмка · 10 Возврат на базу
Коробка (box)          issued(выдана) → packed → loaded → unloaded → placed → (unpacked) | returned
Вещь (item)            listed → disassembled → wrapped → loaded → unloaded → assembled → placed
Доп. работа (change)   proposed → approved(клиент) | rejected → done
```

Шаги зависят от пакета: «Грузотакси» — 1, 2, 5, 6, 7, 9, 10; «Перевозка» — без упаковки (4 только разборка, если заказана);
«Под ключ» — все 10. Обязательные фото на шагах — настраиваются (по умолчанию: 2 «Прибытие — подъезд/парковка»,
3 «до» ≥ 4 фото, 9 «после» ≥ 4 фото + подпись).

## 5. Данные (Cloudflare D1, SQLite) — `db/schema.sql`

Главная идея — **журнал событий** `events` (только добавление). Каждое действие в приложении — событие с UUID,
созданным на телефоне → без интернета копится в очереди, при связи уходит; повтор того же UUID сервер пропускает.
Таблицы-«проекции» (jobs, boxes, stages…) обновляются из событий — история и лента заказа строятся из журнала.

Основные таблицы: `clients`, `leads`, `offers`, `jobs`, `job_addresses`, `job_items`, `job_changes`, `stages`,
`boxes`, `photos`, `staff`, `vans`, `assignments`, `time_entries`, `payments`, `invoices`, `incidents`, `box_stock`,
`events`, `settings`. Поля — в `db/schema.sql`.

Фото — R2 (`media/<job>/<stage>/<uuid>.webp` + превью 400 px), телефон сжимает сам (WebP, длинная сторона 1600 px,
≈200–350 КБ). В строке `photos`: этап, тип (before/after/damage/box/parking/signature/odometer), кто, когда, координаты,
SHA-256 (доказать, что фото не меняли).

## 6. Коробки и QR

- Наклейки печатаются рулонами: уникальный код `MB-7F3K2` + QR (`https://melbus.pl/b/MB-7F3K2`) + цветная полоса
  комнаты (как в фирменном стиле: кухня, спальня, гостиная, детская, кабинет, ванная, прихожая, балкон/гараж).
- **Упаковка:** в приложении выбрать комнату → сканировать QR → 1–3 фото содержимого → (необязательно) голосом/текстом
  «тарелки, кастрюли» → флажки «хрупкое», «коробка первой ночи». Номер в заказе присваивается сам (Кухня · 07).
- **Погрузка:** сканировать каждую коробку у буса → «38 из 40 загружено», список недостающих (ничего не забыть!).
- **Выгрузка:** скан → приложение подсказывает комнату в новой квартире (план комнат с цветами задаёт клиент/бригадир).
  «40 из 40 на месте».
- **Клиент** сканирует QR камерой: если на телефоне открыта его страница переезда — видит фото содержимого;
  чужой человек видит только «Коробка MELBUS» (без содержимого).
- Без сети: сканирование и фото копятся в телефоне, отправляются потом.
- Сканер: `BarcodeDetector` (Android Chrome), запасной — jsQR (iPhone Safari).

## 7. Учёт времени

События: `day_start` (на базе/у буса), `arrive`, `stage_start/stage_end`, `break_start/break_end`, `leave`, `day_end`.
Координаты берутся **только в момент события** (не постоянное слежение) — сотрудники подписывают уведомление
(Kodeks pracy art. 22³: мониторинг — только с уведомлением; GPS машин — отдельно). Пульт показывает план vs факт:
«по оферте 8 ч, факт 7 ч 20 мин», себестоимость (часы людей × 40 zł + бус + коробки) и прибыль заказа.
Факт по вещам (минуты на шкаф/кровать) → отчёт «нормы» → менеджер обновляет минуты в `move.ts` (цены точнее).

## 8. Доп. работы (УТП «без доплат на месте»)

Бригадир в приложении: «Клиент просит…» → выбирает из каталога (`EXTRAS` из move.ts, цена известна) или пишет своё
(цену ставит менеджер) → клиент подтверждает **до начала**: подпись пальцем на телефоне бригадира или ссылка в SMS/WhatsApp
→ событие `change_approved` (кто, когда, сумма, подпись). Без подтверждения работа не делается.

## 9. Приёмка и оплата

Шаг 9: список «всё на месте» (коробки 40/40, вещи собраны), фото «после», замечания клиента, подпись, оценка 1–5.
Оплата: задаток онлайн (Przelewy24/Stripe — BLIK, карта) при подтверждении; остаток — терминал у бригады
(BLIK, карта, наличные) — бригадир отмечает способ и сумму, фото чека терминала. Фактура — через сервис с KSeF
(Fakturownia или inFakt API), PDF в R2, ссылка клиенту на странице переезда.

## 10. Экраны

**Приложение бригады (телефон, крупные кнопки — работают в перчатках, 4 языка):**
1. Вход: телефон + PIN. 2. «Сегодня»: «Начать день», заказы дня (время, адрес, бригада, бус). 3. Заказ: клиент
(позвонить), адреса (навигация), этаж/лифт/парковка, особые вещи, заметки менеджера, шаги-лента, таймер.
4. Шаг: чек-лист + обязательные фото + кнопка «Готово». 5. Сканер коробок (упаковка/погрузка/выгрузка) с прогрессом.
6. Вещи: состояние, фото, «повреждение». 7. Доп. работа + подпись клиента. 8. Приёмка: подпись, оплата.
9. «Мой день/неделя»: часы. Без сети — полоска «Нет связи · 12 действий ждут отправки».

**Пульт (компьютер):** Сегодня (живые бригады, тревоги, деньги) · Заявки (канбан) · Оферты · Расписание (неделя ×
бусы/бригады, перетаскивание) · Заказ (лента событий, шаги, фото, коробки, вещи, доп. работы, оплаты, план/факт) ·
Сотрудники (часы за месяц) · Бусы · Склад коробок · Финансы · Отчёты (воронка, средний чек, прибыль, нормы времени) ·
Настройки (цены, допы, шаблоны сообщений на 4 языках, Telegram).

**Страница переезда клиента:** статус-лента (подтверждено → бригада выехала → упаковка 12/40 → в пути → разгрузка →
готово), бригада (имена) и номер буса, коробки по комнатам с фото, доп. работы на согласие, протокол приёмки, фактура,
оплата, просьба об отзыве (только настоящие отзывы).

## 11. Техника

- Тот же репозиторий и Cloudflare Pages: страницы `/team/*`, `/app/*`, `/t/*`, `/b/*` (Astro + небольшие острова),
  API — Pages Functions `functions/api/crm/*`, `functions/api/app/*`. D1 (`DB`), R2 (`MEDIA`), Cron (напоминания),
  позже Durable Objects (живая карта в Пульте) и Queues (обработка фото).
- PWA: manifest + service worker (оболочка офлайн), IndexedDB (заказы на сегодня, очередь событий, фото до отправки),
  фоновая отправка. Web Push — новые заказы бригаде.
- Telegram-бот: новая заявка, оферта принята, бригада выехала/закончила, повреждение, задаток не оплачен.
- SMS клиенту (SMSAPI.pl) — позже; сейчас ссылки уходят в WhatsApp/Telegram от менеджера.
- Стоимость: Cloudflare Workers Paid $5/мес покрывает D1/R2 с запасом (фото ≈ 1,5 ГБ/мес при 100 заказах ≈ $0,02).
